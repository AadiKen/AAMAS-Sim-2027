## Authority decision and conflict notes

Core simulator execution uses `ExperimentConfig` plus registry definitions. Benchmark v2 and v3 config/task schemas are active for separate benchmark workflows and cannot be treated as interchangeable core task or training schemas. This is an integration boundary, not a choice of one authoritative schema for all workflows. The first web slice targets the core `ExperimentConfig` and waypoint primitive. Training integration must select and document an adapter before presenting a unified editor.

The preexisting `/v1/vessels|worlds|scenarios` resource endpoints accept arbitrary dictionaries, and preexisting `/v1/runs` is synchronous and process-local. They remain compatibility prototypes. The new `/v1/configs`, `/v1/experiments`, `/v1/qualify`, and `/v1/jobs` paths provide the supported MVP contract. Existing uncommitted modifications to simulator/runtime files were present at audit time and were left intact.
